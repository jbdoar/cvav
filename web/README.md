# Browser instrument

Plain JavaScript, HTML/CSS, and WebGL 2 shaders. No bundler, Python runtime,
CDN, or runtime npm dependencies. Only these files are deployed:
`index.html`, `style.css`, `app.js`, `engine.js`, `parameters.js`, and `shaders/`.

From the repository root:

```sh
python3 -m http.server 8000 --bind 127.0.0.1 --directory web
```

Open **http://localhost:8000**. Use HTTP locally, not a `file://` URL: modules and
shader loading require a server. Camera access requires HTTPS or localhost.

The demo starts in color mode with synthetic input. Click **Enable camera** to
request video-only permission; **Stop camera** releases it. Nothing is uploaded.
Switching inputs preserves feedback; switching between mono/color clears it.
The synthetic artwork differs from the Python test pattern; the model defaults
match the corresponding Python experiment. Color-only controls are ignored in
mono mode.

Controls include sliders, pause, clear, reset knobs, output-only PNG snapshots,
and output-only full screen where the browser supports it. Tap a parameter's
letter then `+`/`-` to adjust; holding a key continuously adjusts it. Hold Shift
for finer changes. Space pauses, R clears, D restores defaults. Shortcuts do not
intercept typing or native controls when a form control has focus. Click the
page background to return to global shortcuts. Keyboard changes affect this
web implementation; Python retains its existing controls.

The app requires WebGL 2 and `EXT_color_buffer_float`. It uses 640×480 internal
resolution, a 30 Hz target simulation clock, and display refresh via
`requestAnimationFrame`. It suspends iteration in hidden tabs and bounds catch-up
work under load, so slow hardware slows simulated time. A reduced-motion
preference starts it paused. WebGL loss requires reloading the page.

## Tests

```sh
cd web
npm ci
npx playwright install chromium
npm test
```

Playwright launches its own localhost server. Chromium tests cover control/UI
behavior, camera denial, a synthetic camera stream, snapshots, mono/color modes,
mobile layout, unsupported graphics, and shader comparisons against Python.
Actual camera hardware and other browser/GPU combinations still need manual
checking. The automated browser uses SwiftShader, not a physical GPU.

Reference fixtures are generated by the existing Python engine:

```sh
.venv/bin/python web/tests/generate_fixtures.py
```

Regenerate them when deliberately changing the model and inspect numerical
differences. Floating-point storage and interpolation differ between OpenCV and
WebGL, so comparisons use tolerances, not identical image hashes.

## GitHub Pages

The workflow in `../.github/workflows/pages.yml` tests the web implementation and
publishes only the static runtime files from `web/`. It never uploads `reference/`,
Python, dependencies, or browser test fixtures.

One-time repository setup: **Settings → Pages → Build and deployment → Source →
GitHub Actions**. Push the web changes to `main` (or run the workflow manually).
For `jbdoar/cvav`, the default project-site address is expected to be
**https://jbdoar.github.io/cvav/** after successful deployment. Relative asset
URLs support the `/cvav/` prefix. The repository's plan/visibility must support
GitHub Pages. No deployment is implied merely by adding the workflow locally.

See [GitHub's workflow documentation](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages),
[WebGL float rendering](https://developer.mozilla.org/en-US/docs/Web/API/EXT_color_buffer_float),
and [browser camera requirements](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia).
